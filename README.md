# 餐厅管理一体化信息系统

川香居 · 家常菜（堂食扫码点餐）五端一体化系统：顾客扫码点餐 → 服务员确认/代客下单/代客加菜 → 后厨大屏逐道出餐 → 后台收银结账 → 老板后台经营分析。

> 对应设计文档 V6.0（交付目录：`C:\Users\Admin\Desktop\餐厅小程序\`）。本期范围：堂食单店约 20 桌、无外卖、无线上支付（线下收银台结账）。

## 快速启动

前置：仅需 Python 3.8+（开发期 SQLite 零配置；无 Node/MySQL/Redis 依赖）。

```bash
cd backend

# 1) 创建虚拟环境并安装依赖（首次）
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt     # Windows（PowerShell）
# .venv/bin/pip install -r requirements.txt       # macOS/Linux

# 2) 初始化数据库（幂等，可重复执行）
.venv\Scripts\python.exe seed.py                  # Windows（PowerShell）
# .venv/bin/python seed.py                        # macOS/Linux

# 3) 启动后端（默认 127.0.0.1:8001；换端口：.venv\Scripts\python.exe run.py 8000）
.venv\Scripts\python.exe run.py

# 4) 生成桌台测试二维码（可选，二维码内容为桌号如 A01）
.venv\Scripts\python.exe gen_qr.py

# 5) 冒烟测试（可选，96 项断言；会重置数据库，建议用独立临时库跑）
#    另开一个终端：$env:DATABASE_URL="sqlite:///./smoke_test.db"; .venv\Scripts\python.exe run.py 8000
#    然后执行：$env:DATABASE_URL="sqlite:///./smoke_test.db"; $env:SMOKE_BASE="http://127.0.0.1:8000"; .venv\Scripts\python.exe smoke_test.py
.venv\Scripts\python.exe smoke_test.py
```

> 入口脚本（run.py / seed.py / smoke_test.py）已内置 UTF-8 输出设置，Windows 下无需再设置 PYTHONUTF8 环境变量。macOS/Linux 直接运行即可。

## 核心业务规则（V5.5）

- **下单确认**：顾客下单 → 服务员二次确认后才推送后厨；代客下单提交即确认（从桌台进入时自动锁定桌号，无需二次选择）。
- **订单状态机**：待确认 → 已确认 → 已出餐 → 已结账 / 已取消（无「制作中」）。
- **待确认修改**：服务员可在待确认阶段修改订单——调整数量/删除明细/改备注/新增菜品，金额实时重算（小程序顾客端提交的订单需先确认）。
- **补单加菜**：顾客可补单，经服务员确认后推送 KDS 并标「加」。
- **代客加菜**：用餐中的桌台，服务员从桌台详情进入「代客加菜」直接追加菜品（标「加」直达后厨，无需二次确认）；已出餐订单加菜自动回到已确认。
- **结账职责分离**：服务员端无任何结账收款能力（无收款按钮、无结账接口），结账统一由后台「订单收银」完成（admin / cashier 账号）；服务员端「订单信息」仅查看进行中订单与未结账金额。
- **待清台只能服务员下单**：后台结账后桌台自动「待清台」；顾客扫码下单被拒（提示联系服务员），仅服务员「代客下单」可落单并自动解除待清台（服务员也可手动「标记清台」）。
- **KDS 双页**：后厨大屏分「餐品」「主食」两页（共享同一份订单数据，按菜品分类筛选；URL 加 `?tab=staple` 可直开主食页，适合双屏/双工位）；主页面只显示 待出餐 / 出餐中 两栏，逐道单品出餐（幂等，重复点击不重复扣库存）；超时红框、催单置顶标红、语音播报、4 套配色。
- **已出餐独立页**：整单出完的订单不再占主页面，自动汇总到「已出餐」页（KDS 顶栏「已出餐 N →」链接跳转，支持返回看板）；已出餐页展示当日全部整单出完的订单（含已结账，标「已结账」标签），按整单出完时间倒序。
- **订单列表排序**：后台「订单与收银」列表 金额/状态/支付/时间 四列支持点击表头排序（升/降序切换；状态按业务流程 待确认→已确认→已出餐→已结账→已取消，支付按 微信→支付宝→现金、未支付排后）。
- **菜品展示**：菜品支持 emoji 图标与图片 URL 两种展示（后台管理直接维护），顾客端/服务员端按 图片 → emoji 顺序展示，两者皆无时留空（不显示首字）；菜单接口携带分类 ID，服务员端/小程序按菜系筛选正常显示。
- **餐具默认**：小程序选择用餐人数时，餐具份数默认同步为该人数（仍可手动增减）。
- **库存**：BOM 按「标准用量 ×(1+损耗率)」扣减并记录流水；红（≤安全线）黄（≤1.3 倍）两级预警 + 一键生成采购单。
- **AI 经营分析**：OpenAI 兼容国产大模型（DeepSeek/通义/智谱），密钥仅存服务端，只上传聚合数据；未配置时本地规则模板兜底。
- **结账**：后台「订单与收银」结账收款——应收 = 菜品合计 + 餐具费（每人 ¥1），可录优惠金额（≤应收）、选择收款方式（现金/微信/支付宝）、实际收款金额人工输入确认；**优惠 + 实收恒等于应收**：前端改任一金额自动联动另一金额，后端以实收为准自动补齐优惠（只传优惠则实收自动=应收−优惠，超应收拒绝）；收款成功后提示打印小票，已结账订单可随时补打；营业额等统计按实收金额计；结账后桌台自动「待清台」。

## 核心业务规则（V5.9 增补：餐具费与打印小票）

- **餐具费**：每人 1 元，堂食与外带统一收取。顾客端购物车/服务员端代客下单选择用餐人数后**自动累计进应收**（应收 = 菜品合计 + 餐具费）；修改人数时餐具费随之重算，餐具份数仍默认跟随人数可手动微调。
- **计费口径统一**：订单存储独立餐具费字段，后台订单列表「应收」列、结账弹窗（菜品合计 + 餐具费 = 应收金额）、顾客端订单详情、服务员端订单卡片/收银台、营业额与客单价统计全部按「含餐具费」的应收/实收口径计算；优惠 + 实收 = 应收 的联动与校验同样基于新应收。
- **打印小票**：后台结账收款成功后自动提示「是否立即打印小票」，一键弹出浏览器打印对话框（58mm 小票版式：店名/单号/桌台/时间/明细/餐具费/优惠/实收/收款方式）；已结账订单在详情弹窗可随时「🖨 打印小票」补打。

## 核心业务规则（V6.0 增补：KDS 加菜卡片 / 外带打包盒 / 免单 / 开门与结单 / 小程序分类跳转修复）

- **KDS 加菜独立卡片**：加菜确认后不再把原单拉回「出餐中」，而是在「待出餐」栏独立生成一张橙色「加菜」卡（标注「出完自动并入原单」）；原单卡片保留在原位置并显示「本桌有加菜在待出餐」提示。加菜单全部出餐完成后自动并入原单（并入的明细仍标「加」），待出餐不再显示加菜单。出餐中/待出餐的基础卡只统计自身明细，互不占用。
- **外带打包盒计费**：外带单不再选择用餐人数（系统固定按 1 人），改为选择**打包盒数量，每盒 1 元**（外带下单与修改弹窗均为「打包盒数量」步进器）；应收 = 菜品合计 + 打包盒费；结账与小票明细按「打包盒费」单独列示（堂食仍为「餐具费」）。
- **免单**：后台结账新增「免单」收款方式——实收 0 元、优惠全额冲抵应收，**必填免单原因**（未填拒绝），原因随订单留存并在小票打印；免单订单**按应收金额计入营业额**，工作台与结单对账单独列示「免单金额」（不含在线收/现金）。
- **开门（营业开始）**：后台新增「营业管理」页——开门助手提示当天日期/星期、天气（固定查询山西运城盐湖区，免费在线天气接口自动获取、无需输入，断网降级为「天气未获取」）、零钱箱准备金额（默认 100 元可改）、原料库存红黄预警与注意事项；同日重复开门为更新（幂等）。
- **结单对账（营业结束）**：每日一次——系统自动汇总当日系统现金/微信/支付宝实收与免单金额（按应收）、订单数；输入钱箱现金实点金额后，差额 = 钱箱实点 − 开门零钱 − 系统现金实收，对平即「钱对得上」；同日重复结单为更新对账（幂等）；展示近 7 日钱箱统计，核心保证钱能对上账。
- **小程序分类跳转修复**：左侧分类点击与右侧滚动联动定位由「视口相对位置」改为「内容相对位置」（减去滚动容器偏移与已滚动距离），并在菜品图片加载完成/滚动结束/动画后重算，修复「点主食跳到汤类」的错位问题。
